# Requirements Bootstrap Template

When `doc/requirements.md` does not exist, `/plan` bootstraps it using this structure.

## Initial File Content

```markdown
# Requirements — travis

> Generated by `/plan` on <date>. Maintained via triage synthesis.

## Conventions

- **ID format**: `REQ-<COMPONENT>-<SEQ>` (e.g., `REQ-AUTH-001`)
- **Priority**: Critical > High > Medium > Low
- **Language**: "shall" = mandatory, "should" = recommended, "may" = optional
- **Quality**: ISO/IEC/IEEE 29148 — no banned verbs (handle, manage, support, ensure, process)

## Requirements

<!-- Requirements are organized by component. Each requirement includes:
     - ID, Title, Description (shall/should statement)
     - Rationale (why), Source (triage branch), Priority
     - Acceptance Criteria (testable conditions)
-->
```

## Bootstrap Procedure

1. Create `doc/` directory if it does not exist: `mkdir -p doc`
2. Write the template above with `travis` replaced by the project name (derive from repo name or ask the user)
3. Stage and commit: `git add doc/requirements.md && git commit -m "docs: bootstrap requirements document"`
4. Proceed with triage synthesis — append requirements after the `## Requirements` heading
